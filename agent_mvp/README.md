# Fed Agent - Package Documentation

For a clean-checkout installation, start with the [repository README](../README.md).

This package turns a natural-language research request into a constrained,
reviewable Vantage6 descriptive-statistics task. The LLM extracts intent only;
deterministic components resolve semantic classes, deployment IDs, algorithm
arguments, and the final Vantage6 payload.

Unsupported research conditions stay protected across follow-ups, results are
validated before a report is written, and `/report` rebuilds a report from a stored
result without repeating the computation; see [study sessions](docs/STUDY_SESSIONS.md).

## Directory Layout

| Directory | Purpose |
| --- | --- |
| `src/federated_agent/` | Agent implementation and trusted script templates |
| `catalogs/` | Algorithm, semantic-source metadata and execution-template catalogs |
| `config/` | Deployment, data availability, registry and policy configuration |
| `examples/` | Authored research-request acceptance cases |
| `tests/` | Automated regression tests and synthetic fixtures |
| `scripts/` | Evaluation, registry maintenance and packaging utilities |
| `docs/` | Design, operations and handoff documentation |

`src/federated_research_agent.egg-info/` is editable-install package metadata;
keep it while using the installed environments. Python `__pycache__` directories
are disposable and may be regenerated by Python.

The root `agent.cmd` launcher writes sessions to `../integration/agent-demo/`. For
other runs, use an explicit output directory under `../integration/` to keep
generated files out of this source directory.

The execution lifecycle follows the fixed researcher-side template supplied by
Joshi: connect, authenticate, submit, wait, retrieve and save. The LLM proposes
research-dependent values; catalog-backed tools validate and bind them into that
template. It does not rewrite execution code. See
[the fixed-template requirement](docs/FIXED_TEMPLATE_WORKFLOW.md) for the exact
division of responsibilities and the difference between Joshi's training example
and the currently supported descriptive-statistics contract.

The default algorithm is descriptive statistics. Additional compatible contracts
can be registered in `src/federated_agent/data/catalogs/algorithms.json` without editing the planner.
The default execution backend is mock; `--backend vantage6` enables the explicitly
confirmed synthetic 4.15 sandbox through a bounded SDK worker. Real execution uses
operator-owned `src/federated_agent/data/config/policy.json`, with `allow_all` as the development default
and an action-specific OPA provider available for future institutional policies.
See [the architecture audit and extension guide](docs/ARCHITECTURE_EXTENSIONS.md)
for enforced policy boundaries, versioned metadata publication/synchronization
and trusted execution-template updates.

## Real CLI demonstration

Read [LIVE_CLI_DEMO.md](docs/LIVE_CLI_DEMO.md) for the Windows launcher,
DeepSeek/local-model setup, interactive clarification, exact-task confirmation,
real execution, local charts and error examples. From the repository root, run
`.\agent.cmd`; it uses the isolated Agents SDK environment and `start_agent.py`
with DeepSeek. Add `--agent-runtime json` for the JSON runtime, which local models use.
Read [the English operations and registry guide](../AGENT_OPERATIONS_AND_REGISTRY.md)
for current SSH connectivity, production access options, JSON field rationale and
the original synchronization proposal. Its implemented successor and exact
deployment limits are documented in [ARCHITECTURE_EXTENSIONS.md](docs/ARCHITECTURE_EXTENSIONS.md).
The interactive CLI now supports real DeepSeek SSE replies, arrow-key choices,
multi-select hospitals and inline task review. `--plain` disables cursor UI;
`--no-stream` disables SSE and the additional model explanation call. Deterministic
checks still control task execution; the policy extension remains allow-all.
Pure greetings/thanks and supported model/date/time questions bypass research
planning. `/model` reads this session's configured model and agent runtime;
`/date` and `/time` read the computer's local clock. These answers do not call the
LLM, refresh the catalog, change a pending study, or submit a task. Whole-turn
matching prevents a compound research instruction from being silently discarded.
This is a small system-information route, not unrestricted general chat.
Replies default to English;
Chinese researcher input selects Chinese explanations. Menu selections preserve
the last language, and a later English message switches back. A greeting followed
by an actual research instruction is still handled as a task.
The known single-site numerical defect is blocked through catalog constraints.

## Stateful studies and recovery

The CLI now saves study context across restarts. `/sessions` and `/resume <id>`
restore it without executing; `/plan` and `/history` show the study and task IDs.
Follow-ups use constrained field updates, preserve omitted requirements, and
require a fresh review/confirmation for each new task. `/recover <turn-id>` reads
an already submitted Vantage6 task without creating another one. Missing task IDs
require operator reconciliation, never blind retry. `/review` revalidates an
unexecuted plan; `/new` clears context without deleting history or cancelling
remote jobs. Read [STUDY_SESSIONS.md](docs/STUDY_SESSIONS.md) for usage, audit files,
tests and remaining limitations.

A new study must explicitly select a dataset. Missing selection produces a
clarification even when the deployment has a default or only one candidate.
Follow-ups retain an existing choice visibly; explicitly clearing the choice
requires a new selection. See [dataset selection](docs/DATASET_SELECTION.md) for
candidate filtering and the separate task-confirmation step.

The default Ubuntu data-availability snapshot was reverified on September 17 and
expires at `2026-09-18T01:01:43.497792+00:00`. New managed submissions require current
operator evidence. Expiry is explicit at startup; it does not disable read-only
task recovery. Never extend snapshot timestamps without rechecking the nodes.

## Researcher-facing diagnostics

Every CLI response now also writes `researcher_response.md`: what is wrong,
which field needs attention, concrete next steps, and compatible alternatives
from the same live catalog snapshot. Suggestions are not authorization grants
or automatic replacements for the research question. Approximate variable names
now require confirmation instead of being silently resolved.

An optional `--data-availability-config` supports operator-maintained, expiring
metadata snapshots. Explicit unavailability and policy denials stop preparation;
unknown availability and the default allow-all policy are clearly labeled.
Configured checks run again before execution. See
[researcher feedback and preflight guide](docs/RESEARCHER_FEEDBACK.md) for examples,
the trust boundary, runtime failure handling and remaining integration work.

```powershell
$env:PYTHONPATH = "src"
python scripts/generate_feedback_examples.py --output output-feedback-examples
```

These are labeled offline examples, not real hospital or authorization results.

## Current pipeline

1. Reload and validate `src/federated_agent/data/catalogs/algorithms.json`, recording its version and SHA-256.
2. Convert the request using that catalog into a strict `ResearchPlan` containing variable and site
   names, never organization IDs.
3. Resolve variables against the STRONG AYA JSON-LD schema.
4. Resolve site names through a versioned deployment registry.
5. Select an enabled algorithm from the same snapshot and validate its site scope.
6. Compile a Vantage6 4.15 task using declarative bindings and JSON Schema validation.
7. Record the source and version of automatically populated fields.
8. Pass the task through the replaceable policy interface.
9. Write `prepared_task.json` and bind confirmation to its task and catalog hash.
10. Before execution, reject a changed catalog and require matching confirmation.

Missing or ambiguous variables/sites produce a machine-readable
`clarification.json` instead of guessed IDs or an invalid task.

## Prepare an offline demonstration

```powershell
$env:PYTHONPATH = "src"
python -m federated_agent `
  --provider demo `
  --request "Calculate descriptive statistics for gender and survival status in hospital 1 and hospital 2." `
  --output output-demo
```

This writes:

- `response.json`: the current response status and catalog reference.
- `catalog_snapshot.json`: the byte-exact catalog used for this request.
- `prepared_task.json`: the complete plan, resolution, policy decision, and
  confirmation ID.
- `task_spec.json`: the versioned Vantage6 task and field provenance.
- `run_vantage6_task.py`: a credential-free Vantage6 4.15 client script.

Review the prepared artifact, then execute the exact mock task:

```powershell
$prepared = Get-Content output-demo/prepared_task.json | ConvertFrom-Json
python -m federated_agent `
  --execute-prepared output-demo/prepared_task.json `
  --confirm $prepared.confirmation_id `
  --output output-demo
```

Changing the task after preparation invalidates its confirmation ID. Changing the
catalog requires regenerating the task and script. Use a separate output folder
per request; failed requests do not delete artifacts left from previous runs.

## Live algorithm registry

Edit [`src/federated_agent/data/catalogs/algorithms.json`](src/federated_agent/data/catalogs/algorithms.json) to add, update or disable
algorithms. Every default agent request and capability query rereads it; no model
retraining or restart is required. The LLM and compiler share one snapshot per
turn. Missing or malformed files stop the request instead of using stale memory.

```powershell
python -m federated_agent --validate-catalog --output output-catalog-validation
python -m federated_agent --list-algorithms --output output-catalog-list
```

Use `--catalog path/to/algorithms.json` to select a different registry. See the
[registry design and update guide](docs/ALGORITHM_REGISTRY.md) for fields,
declarative argument bindings, declared versus verified availability, and the
limits of file-only additions. Unknown execution adapters cannot compile.

The [roadmap](docs/DEVELOPMENT_ROADMAP.md) lists the deliverables that remain open.

## Use DeepSeek remotely

The API key is read locally at runtime and is never included in a prompt or
generated artifact. Supply a UTF-8 file containing only the bare key:

```powershell
$env:PYTHONPATH = "src"
python -m federated_agent `
  --provider deepseek `
  --deepseek-api-key-file "$HOME\Desktop\deepseek-api.txt" `
  --request "Describe gender across hospital 1 and hospital 2" `
  --output output-deepseek
```

Alternatively configure `DEEPSEEK_API_KEY_FILE` or `DEEPSEEK_API_KEY`. An explicit
file overrides both; an invalid file stops startup instead of falling back.
The Windows demo launcher auto-discovers `~/Desktop/deepseek-api.txt`, ahead of
the key environment variable. Keep this plaintext file private and outside the
repository; do not include it in handoff archives.

The research request and public algorithm metadata are sent to the remote LLM.
Never include patient-level data, credentials, or confidential records in either
the request or the catalog. Registry contents are not automatically redacted.

## Use a local model

Any local service exposing an OpenAI-compatible chat-completions endpoint, such as
Ollama, can use the same planner contract through the JSON runtime. The
[evaluation results](evaluation/RESULTS_2026-10.md) compare local models and the
safeguards they need:

```powershell
python -m federated_agent `
  --provider local `
  --llm-endpoint "http://localhost:8000/v1/chat/completions" `
  --model "local-model-name" `
  --request "Describe gender across hospital 1 and hospital 2"
```

## Deployment registry

[`src/federated_agent/data/config/demo_deployment.json`](src/federated_agent/data/config/demo_deployment.json) contains public
execution metadata: Vantage6 version and endpoint, collaboration ID, central
organization ID, researcher-facing site aliases, organization IDs, database
labels. Algorithm images, signatures and availability belong only in
`src/federated_agent/data/catalogs/algorithms.json`. The deployment's `.invalid`
endpoint makes clear that it is not a real environment.

Create a separate deployment file after Len or Joshi provides the actual sandbox
values, then pass it with:

```powershell
python -m federated_agent --deployment-config my-sandbox-deployment.json
```

Do not put usernames, passwords, API keys, or organization private-key paths in
the deployment registry. The generated script reads these at runtime:

```text
VANTAGE6_USERNAME
VANTAGE6_PASSWORD                 # optional; otherwise getpass is used
VANTAGE6_ORGANIZATION_KEY         # optional private-key filepath
FEDERATED_AGENT_CONFIRMATION      # optional non-interactive confirmation
FEDERATED_AGENT_CATALOG           # optional live catalog path after moving a script
```

The server endpoint is deliberately not a runtime override: it is part of the
reviewed confirmation fingerprint. Change the deployment registry and prepare a
new task when targeting another environment.

## Verified contract and upstream drift

The default contract pins
`ghcr.io/strongaya/v6-descriptive-statistics:v2.1.0`. Its released `central()`
implementation accepts `organisation_ids` and depends on Vantage6 algorithm tools
4.15.

The upstream `algorithm_store.json` is inconsistent: it advertises
`organization_ids`, `return_partials`, and Vantage6 4.12. The newer `central.py`
shared by the colleague and currently on `main` instead uses
`organisations_to_include`. The catalog entry in `algorithms.json` therefore follows
the verified v2.1.0 implementation signature; a newer signature needs its own entry
with matching input bindings. Never pair the newer signature with the v2.1.0 image
without checking the image deployed in the target collaboration.

Sources:

- <https://github.com/STRONGAYA/AYA-cancer-semantic-map>
- <https://github.com/STRONGAYA/v6-descriptive-statistics>
- <https://docs.vantage6.ai/en/version-4.15.0/user/pyclient.html>

`scripts/sync_catalogs.py` refreshes the semantic map and the pinned v2.1.0
upstream algorithm metadata snapshot. It does not overwrite the maintained
`algorithms.json` execution contracts.

## External access and scope

- The Ubuntu synthetic deployment values have now been returned and are in
  `src/federated_agent/data/config/ubuntu_sandbox.json`; its local SSH tunnel must remain open.
- A working model endpoint/key and locally entered Vantage6 researcher credentials.
- A current, operator-verified data availability snapshot. The bundled synthetic
  snapshot expires rather than silently claiming permanent availability.

`--backend mock` remains offline. Real execution requires `--backend vantage6`
and `--confirm-synthetic-unencrypted-sandbox`; no production encryption or OPA
configuration is implied. Managed exported scripts route execution back through
the agent for fresh checks instead of bypassing them.
